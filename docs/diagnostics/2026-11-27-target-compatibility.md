# 抖音与极速版的跨版本兼容

目标是保留旧布局识别能力，同时适配改名后的节点；不根据版本号限制识别或强制用户更新抖音。

## 本次发现与修复

定向查询原先在发现 `desc` 等已知ID后省略“选集、全集、第”的查询。这会让仍有介绍栏、依靠集数和选集判断上下文的布局丢失播放器锚点。

新增 `TargetCompatibilityTest.descriptionIdDoesNotHideEpisodeAndSelectionAnchorsInOlderLayouts`，先复现失败，再改为始终查询这些锚点。保留原ID查询捷径、节点数量限制、上下文和广告证据要求。

新增测试覆盖两个包名、旧ID `b4=/cq-`、改名ID `b5i/crf`、广告介绍、普通介绍、否定广告文案以及新安装默认启用两个目标。节点为合成样本，不是对历史APK逐版本测试。

## 当前证据边界

- 抖音41.2.0：此前真机观察到主窗口带其他应用小窗及可操作失焦小窗的自动跳过。
- 抖音41.3.0：已读取真机改版节点并补充回归；修复包安装后的持续自动跳过仍待用户验证。
- 抖音极速版：目标包名及媒体会话处理已存在；本次补充识别节点回归，尚无极速版真机通过记录。
- 更早历史版本：保留现有旧ID与文字规则；没有足够证据给出连续版本范围或“全部兼容”的保证。

## 后续界面建议（尚未实施）

在设置的应用信息区域分别展示本机安装版本、最近真机实测版本/日期和验证状态。使用“未验证”描述未知版本，不使用“最高支持版本”或根据数字大小判定不兼容。只在进入页面、返回应用时刷新版本信息，无需后台轮询。

已有运行日志复制报告包含两个应用的当前安装版本，便于将漏识别与版本变动对照。若后续添加页面，版本不匹配本身不应阻止运行或提示必须升级；应优先依据日志判断权限、服务、布局或媒体控制问题。
