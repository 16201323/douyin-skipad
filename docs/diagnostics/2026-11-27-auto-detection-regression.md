# 手动正常、自动失效的现场排查

用户报告1.5.3使用数日后自动跳过失效，悬浮窗手动仍能跳。手机PHK110、Android16；正式助手1.5.3的前台服务运行，无障碍已绑定，自动检测日志持续产生，目标窗口选择正确。

抖音当前41.3.0/versionCode410301，系统lastUpdateTime为2026-11-27 06:34:04；此前实验为41.2.0。用户描述的首次失效时间是“昨天”，因此不能单凭更新时间解释整个起始时间，本次以当前现场证据定位。

日志稳定返回播放器上下文不足：episode=true、selection=false、drama=false、exit=false、panel=false。不是锁屏、缺授权、选错窗口或发送媒体指令失败。

采集用户广告页节点后发现，介绍栏仍为desc，退出入口由旧b4=变为b5i，底部剧名为crf。实际介绍末尾含广告，页面同时有退出短剧和底部短剧标题。

旧inspectFocused因desc可见而认为knownLayout=true，从而省略布局文字查询；旧退出入口又要求ID=b4=，导致出口和剧名同时漏读。广告证据被播放器上下文门槛挡住。这解释了当前场景手动控制正常、自动判断失效。

修复：始终定向查询退出短剧与短剧文字，其他布局查询仍有界；入口结合精确文字、顶部/左侧位置及尺寸判断，不再依赖混淆ID。保留评论排除、广告证据、正常画面确认和窗口保护。先复现新ID/旧介绍栏并存时旧实现失败，再验证修复；新增直播组合、正常介绍、不是广告及正文伪入口回归，完整测试与Lint、release构建通过。
