# 抖音短剧广告跳过助手

> 仅支持 **Android** 系统（Android 7.0 及以上），不支持 iOS / 鸿蒙独立应用。

一个 Android 短剧辅助工具：在抖音短剧播放时，**手动点击**或**自动检测**跳过广告。

## 开发起源

本程序的思路来源于一个日常发现：**车载蓝牙连接手机时，按方向盘 / 车机上的「下一曲」键，抖音短剧里的广告会被直接跳过**。调研后得知，抖音短剧播放器实现了 MediaSession 的 `onSkipToNext()` 回调，系统级「下一曲」指令会让播放器切到下一集，无论当前是否在广告界面。

本程序正是以此为核心思路，通过 Android 的 MediaSession API 复现「下一曲」跳过能力，并在此基础上调研扩展：用无障碍服务检测广告界面、实现手动悬浮窗一键跳过与自动检测跳过、悬浮窗交互与统计等功能，逐步发展为一个完整的工具。

> 广告出现后需要读取证据、再次确认并等待播放器响应。实际耗时随广告样式、手机与播放器状态变化，不保证固定时间或所有广告均可跳过。

## 功能

- **悬浮窗一键跳过**：抖音播放界面显示悬浮按钮，单击即跳过当前广告（含倒计时中的广告）
- **自动跳过**：默认开启，打开程序并完成必要授权后自动运行，无需悬浮窗；识别与二次确认后尝试跳过，实际耗时取决于页面与播放器
  - 支持**倒计时广告**（识别「X 秒后可继续看下一集」等文案）
  - 支持部分**无倒计时广告**（结合播放器上下文与可见广告角标；不以「免广告」作为广告证据）
- **广告检测间隔可调**：在 App 内设置前台检测/广告识别的轮询频率（200~2000ms，默认 500ms），越小响应越快、越耗电
- **跳过统计**：首页展示今日 / 本周已跳过次数（跨天、跨周自动归零）
- **悬浮窗自定义**：颜色、透明度、大小、形状、文字、图片内容均可配置
- **悬浮窗交互**：
  - 单击跳过广告；长按收起 / 恢复
  - 拖到屏幕边缘停留 2 秒 → 自动收起成小长条
  - 收起态横向滑动或向屏幕内侧拖动 → 恢复正常大小
  - 位置自动记忆，重启后恢复到上次位置
- **多应用支持**：抖音、抖音极速版

## 原理

### 跳过：MediaSession skipToNext

抖音短剧播放器实现了 `MediaSession.Callback.onSkipToNext()` 接口。调用 `MediaController.transportControls.skipToNext()` 时，播放器切到下一集，**无论当前是否在广告界面**——这就是车载蓝牙「下一曲」键能跳过抖音广告的原因。

### 广告检测：无障碍节点文字

通过无障碍服务读取当前界面的文字节点，匹配广告页独有文案来判定是否为广告：

| 广告类型 | 识别文案 |
|----------|----------|
| 可直接上滑 | 「上滑继续观看短剧」 |
| 倒计时中 | 「X 秒后可继续看下一集」、「秒后可继续上滑看剧」、「倒计时结束后可滑动」 |
| 无倒计时广告 | 可见独立角标「广告」或「广告1/3」 |
| 排除误判 | 不使用「免广告」「无广告」或任意长文案的「广告」后缀 |

> 检测到广告后采用**双阶段确认**：强证据等待 120ms、角标证据等待 300ms，重新读取页面仍满足条件才提交跳过请求。

> ⚠️ 抖音 MediaSession 在正片和广告时状态完全相同（metadata=null, state=NONE），**无法仅通过 MediaSession 区分正片和广告**，因此必须依赖无障碍读取界面文字。若广告文字画在视频画面（SurfaceView）上，无障碍读不到，则该类广告暂无法自动识别。

## 技术栈

- **语言**：Kotlin
- **构建**：Gradle (Kotlin DSL)，JDK 17
- **minSdk**：24（Android 7.0）

### 核心组件

| 组件 | 作用 |
|------|------|
| `FloatingButtonService` | 前台服务，管理悬浮窗显示、拖动、贴边收起、位置记忆、自动跳过调度 |
| `FloatingView` / `ShapePainter` | 悬浮窗绘制（形状、图片、文字） |
| `MediaControlService` | `NotificationListenerService`，获取 MediaSession，执行 skipToNext |
| `SkipAdAccessibilityService` | `AccessibilityService`，前台应用检测、广告节点文字检测 |
| `ConfigManager` | SharedPreferences 配置管理（样式、App 列表、自动跳过、检测间隔、统计、位置记忆） |
| `MainActivity` | 主界面：权限引导、样式设置、自动跳过开关、检测间隔、统计展示 |
| `ColorPickerDialog` | HSV 颜色选择对话框 |
| `AdDataLogger` | 本地数据采集（**已停用**，仅供调试，正式版不再后台写文件） |

### 关键技术点

1. **NotificationListenerService**：必须启用才能通过 `MediaSessionManager.getActiveSessions()` 获取所有活跃 MediaController。
2. **悬浮窗权限**：仅使用手动悬浮按钮时需要 `SYSTEM_ALERT_WINDOW`，自动跳过无需此权限。
3. **目标窗口检测**：通过 `AccessibilityService.getWindows()` 获取交互窗口，按包名、层级与可操作区域选择目标；焦点不作为必要条件。Android 11+ 使用真实 Region 区分小窗边框和透明中心，旧系统采用矩形。
4. **跳过操作只作用于当前目标 App**：自动跳过与悬浮窗开关独立，主动暂停后保持暂停。执行跳过时重新校验窗口，并且只控制该应用的一个媒体会话。

## 使用说明

### 1. 开启必需权限

首次启动会引导开启：

1. **通知使用权**（NotificationListener）—— 获取 MediaSession，执行跳过
2. **无障碍服务**（AccessibilityService）—— 前台检测 + 广告检测
3. **通知权限**（Android 13+）—— 显示运行状态和暂停/恢复入口；拒绝不阻止后台前台服务运行

悬浮窗权限仅在主动打开“显示悬浮窗”时请求；没有无障碍时手动操作另需使用情况访问。

> 权限状态在首页实时刷新；若无障碍显示 ✗，点「去开启无障碍服务」直达系统设置页开启后返回即可。

### 2. 重要：防止无障碍被系统杀掉（OPPO / ColorOS 等国产 ROM 必做）

国产 ROM 会在后台强杀进程（ColorOS 的 `o-stop`），并**自动撤销已开启的无障碍服务**，导致自动跳过失效、权限状态反复打叉。请务必设置：

1. **应用信息 → 电池 / 耗电管理**：允许后台活动，关闭所有省电限制、应用速冻
2. **应用信息 → 自启动**：打开
3. **多任务界面**：下拉本 App 卡片锁住（出现 🔒）
4. **不要使用「一键清理 / 加速」**：会触发强杀并撤销无障碍

设置生效后，进程稳定、无障碍不再掉线，自动跳过才能持续工作。

### 3. 配置与启动

1. 勾选支持的应用（抖音 / 抖音极速版）
2. （可选）自定义悬浮窗样式：颜色、透明度、大小、形状、文字 / 图片
3. 自动跳过默认开启，授权完成后启动；首页和通知栏可暂停/恢复，主动暂停会保留
4. （可选）开启“显示悬浮窗”获得手动按钮；其开关独立于自动跳过

### 4. 看剧

打开抖音刷短剧：

- **手动**：遇到广告单击悬浮窗跳过
- **自动**：无需显示悬浮按钮，识别到支持的广告后自动尝试跳过，可在首页查看已确认的今日 / 本周次数

### 悬浮窗操作

| 操作 | 效果 |
|------|------|
| 单击 | 跳过广告（正常态）/ 恢复显示（收起态） |
| 长按（>0.6 秒） | 收起 / 恢复切换 |
| 拖动 | 移动位置；拖到屏幕边缘停留 2 秒自动收起 |
| 收起态横向滑动 | 恢复正常大小，可继续拖动 |

## 已知限制

- **红果免费漫剧无法跳过**：其播放器未实现 `onSkipToNext()` 回调，MediaSession 方式无效
- **画在视频画面上的广告文字**：无障碍读不到 SurfaceView 内的字幕，这类广告无法自动识别（需 OCR 等方案，暂未支持）
- **自动跳过依赖无障碍**：无障碍被系统杀掉则自动跳过失效，见上文「防止无障碍被系统杀掉」
- **系统缩略预览**：小窗若缩成仅有系统预览、没有应用节点的状态，无法读取广告；展开为可操作小窗后可在失焦时继续识别。

## 1.0.2 事件检测优化

- 窗口、内容、文字变化可直接触发已运行服务检测；不会用事件拉起已停止的服务。保留可调的补充轮询。
- 优先定向查询已验证控件与少量关键词，组合播放器锚点、广告提示、角标位置与尺寸，排除评论、搜索、会员区域。仅小树保留有界遍历兜底；可编辑面板或上下文不完整时不自动跳过。
- 高置信提示独立等待 120ms 后重新读屏，角标证据等待 300ms。事件任务保留最早期限，内容事件触发的扫描最短间隔 80ms，避免事件风暴不断推迟复核或持续遍历。
- 同一应用的持续广告只提交一次请求；倒计时变化、短暂空树、切到其他应用不会解除已执行锁。只有同一播放器窗口内连续观察到无广告 800ms 后才重新允许下一条广告，另保留 700ms 操作保护。
- `AdPipeline` 日志记录证据级别、扫描耗时、请求和确认时间；不保存截图或页面全文。日志中的时间使用 uptimeMillis，同一开机周期可比较。
- 模拟节点树测试可验证慢轮询下的快速事件响应；实际从广告出现到画面恢复的速度、不同抖音版本的覆盖率仍需真机广告样本验证。OCR 未加入，视频像素中的广告标识仍可能无法自动识别。

- 已按本机真实布局适配“第 N 集 | 介绍”＋“短剧 · 剧名”。对尾部拼接的广告标识，额外要求已验证的“退出短剧”控件、底部介绍控件 ID 和位置共同成立，不恢复任意文本后缀匹配。
- 真机节点检查样本为 42～258ms，正式服务另记录一次 85ms；这不是广告出现到消失的端到端时间保证。39 项回归测试通过，仍需更多广告样本评估漏识别率和误跳率。

- 设置 → 最近识别记录：仅本机保留最近100条状态、命中规则、请求及确认结果，可以刷新、复制、清空，不采集截图或页面全文。
- 规则修改后重新进行广告二次确认，发送途中旧结果不能继续执行；确认记录保留原来命中的规则名称。
- 设置 → 关于 → 历史版本与下载：展示可选中复制的 GitHub Releases 列表，提供“打开历史版本”和“复制地址”。地址为 https://github.com/16201323/douyin-skipad/releases ，可自行选择版本下载。
- 75项回归测试通过，Lint 0错误、8警告；已检查新页面的浅色/深色真机布局。直播识别基于模拟节点验证，仍需真实广告节点和播放器响应检验，不能保证所有直播广告均可跳过。

## 1.4.1 自动更新

- 设置 → 关于 → 软件更新：自动检查 GitHub Release 正式版，显示版本说明、下载进度和状态，支持手动检查、下载、取消、重试与安装。
- 下载方式可选：仅 Wi-Fi 自动下载（默认，不使用计费网络）、任意网络自动下载、仅提醒手动下载。手动下载可单独选择本次网络，不更改默认偏好；不在漫游网络自动下载。
- 系统 DownloadManager 持续下载，任务编号和状态保留至重新打开程序；下载完成并校验后通知用户。安装由用户点击发起，首次可能需允许本应用安装更新，并按系统提示确认，不从后台弹出安装器。
- 打开 App 时调度检查，另有12小时周期任务；自动检查6小时节流，系统后台限制可能延迟。关闭自动检查不影响广告识别。
- 安装前重新核对来源、SHA256、文件大小、包名、版本号与当前应用签名。后续发布需沿用当前签名；当前 release 复用本机 debug 签名，其他电脑新生成的 debug 密钥不能作为同签名更新。
- 仅查询固定公开仓库，不内置 GitHub 令牌；保留历史版本打开和复制入口。下载目录由仅限 updates 子目录的 FileProvider 提供只读安装访问。
- 88项回归测试通过，Lint 0错误、10警告；更新页面浅色/深色真机检查通过。验证版用于与最终版之间的真实更新下载检查，系统安装确认仍按设备要求处理。

## 1.5.0 无密钥静态自动更新

- 支持从公开静态 JSON 检查版本，按现有网络偏好自动下载 APK，不需要客户端账号、API Key 或自建服务端。
- 静态站点优先，GitHub 版本与同版本安装包作为备用；下载连接等待、网络等待和 Wi-Fi 等待分别显示。
- 静态清单严格限制来源和版本路径，新增 versionCode 一致性校验，保留大小、SHA256、包名与签名验证。
- [下载站点](https://douyin-skipad-updates.pages.dev)；[发布维护说明](docs/static-update-publishing.md)。旧版 1.4.1 首次需手动覆盖安装新版，以后使用新来源。

## 1.5.1 自动跳过开关与权限检查

- 首页提供独立的自动跳过开关和「检查权限」入口，通知启停后自动同步，显式关闭后重开界面仍保持关闭。
- 区分通知使用权、无障碍授权、无障碍实际连接与后台服务运行，未连接不会显示识别运行中。
- 权限页面区分必需与可选权限；自动识别不需要悬浮窗权限，Android 13+ 通知显示可单独管理。
- 自动构建沿用现有签名，版本号递增后推送 main 即可自动发布 APK 和静态更新文件。
- 自动识别按已启用应用的实时可见窗口选择目标，支持其他应用小窗抢焦点、播放器自身小窗失焦；完全遮挡或移出屏幕时不控制。节点证据不可读或不完整时仍不自动动作。
